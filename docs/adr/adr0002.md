# 📄 ADR-0002: Estrutura de repositório — Monorepo vs Polyrepo

## ✅ Status

Aceito

## 📅 Data

2026-08-28

## 🧩 Contexto

O projeto é composto por três serviços Spring Boot (`product-service`, `order-service`, `notification-service`) mais um cliente Angular. É preciso decidir se cada serviço vive em seu próprio repositório Git (polyrepo) ou se todos convivem em um único repositório (monorepo).

## 🎯 Decisão

O projeto será organizado como **Monorepo**, com todos os serviços e o cliente Angular versionados no mesmo repositório GitHub.

## 🔀 Alternativas consideradas

### 🔴 Polyrepo
- Cada serviço em um repositório separado, com ciclo de vida e versionamento independentes.
- Reflete mais fielmente como algumas empresas organizam microsserviços em produção, especialmente times grandes com deploys independentes.
- Descartado neste momento por aumentar a complexidade de coordenação (múltiplos clones, múltiplos PRs para uma única mudança de contrato, sincronização manual entre repositórios) — custo desnecessário para um projeto de aprendizado solo.

### 🟢 Monorepo
- Todos os serviços, `docker-compose.yml` e documentação (`docs/adr/`) em um único lugar.
- Facilita rodar o ambiente completo localmente (`docker-compose up`) e visualizar o sistema como um todo.
- Simplifica o fluxo de trabalho individual: um único clone, um único histórico de commits, mudanças correlacionadas entre serviços ficam no mesmo PR.
- Mais adequado ao objetivo atual do projeto: aprender a arquitetura de microsserviços, não a logística de múltiplos repositórios.

## ⚖️ Consequências

**✅ Positivas:**
- Setup local mais simples (um clone só).
- Visão unificada da arquitetura, ADRs e documentação.
- Menor fricção para mudanças que atravessam mais de um serviço.

**⚠️ Negativas / trade-offs:**
- Não reflete exatamente o cenário mais comum de mercado, onde cada serviço costuma ter deploy e pipeline de CI/CD independentes em repositórios próprios.
- Se o projeto crescer muito, pode ser necessário migrar para polyrepo no futuro — decisão que pode ser revisitada em uma nova ADR.
