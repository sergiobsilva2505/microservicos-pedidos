# 📄 ADR-0007: Identificador dos produtos — UUID vs Long auto-increment

## ✅ Status

Aceito

## 📅 Data

2026-08-28

## 🧩 Contexto

O `product-service` precisa de uma estratégia de identificação única para os produtos, usada tanto internamente (chave primária no Postgres) quanto externamente (nos contratos REST consumidos pelo `order-service` e nos payloads dos eventos). As duas opções consideradas foram UUID e `Long` auto-increment.

## 🎯 Decisão

O ID do produto será do tipo **`Long` auto-increment**.

## 🔀 Alternativas consideradas

### 🔴 UUID
- Gera identificadores globalmente únicos sem depender do banco de dados, o que é vantajoso em cenários distribuídos onde múltiplas instâncias geram IDs de forma independente (evita colisão sem coordenação central).
- Mais comum em sistemas distribuídos de maior escala, especialmente quando há geração de ID fora do banco ou múltiplas fontes de escrita.
- Descartado nesta fase por adicionar complexidade (chaves mais pesadas, menor legibilidade em logs/debug, índices menos eficientes em Postgres) sem um ganho claro para o estágio atual do projeto, que tem uma única instância de `product-service` como fonte de escrita.

### 🟢 Long auto-increment
- Mais simples de implementar, ler em logs e debugar durante o aprendizado.
- Suficiente para o cenário atual: uma única fonte de escrita (`product-service`) gerando os IDs via sequência do Postgres, sem necessidade de geração distribuída.
- Chaves mais leves e mais eficientes para indexação no banco relacional.
- Abordagem mais comum como ponto de partida em projetos e tutoriais de microsserviços com Spring Boot.

## ⚖️ Consequências

**✅ Positivas:**
- Simplicidade de implementação e depuração.
- Melhor performance de indexação no Postgres comparado a UUID.
- Adequado ao volume e à natureza do projeto atual (aprendizado, single source of truth por serviço).

**⚠️ Negativas / trade-offs:**
- Expõe um padrão previsível de IDs sequenciais nos contratos públicos, o que em sistemas de produção reais às vezes é evitado por razões de segurança/enumeração.
- Caso o projeto evolua para múltiplas fontes de escrita distribuídas para `product-service`, essa decisão precisaria ser revisitada.
