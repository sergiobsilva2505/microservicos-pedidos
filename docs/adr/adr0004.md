# 📄 ADR-0004: Banco de dados — H2 vs Postgres

## ✅ Status

Aceito

## 📅 Data

2026-08-28

## 🧩 Contexto

Cada serviço precisa de um banco de dados próprio, seguindo o padrão *database-per-service*. Era necessário decidir entre um banco em memória para desenvolvimento rápido (H2) ou um banco relacional real containerizado (Postgres via Docker).

## 🎯 Decisão

Será utilizado **Postgres**, rodando via **Docker**, com uma instância dedicada para cada serviço (`product-db`, `order-db`, etc.).

## 🔀 Alternativas consideradas

### 🔴 H2 (banco em memória)
- Extremamente rápido para subir e rodar testes, zero configuração de infraestrutura.
- Os dados são perdidos a cada restart da aplicação, o que não reflete um cenário realista de persistência.
- Comportamento de tipos, constraints e queries pode divergir sutilmente de um banco de produção real, mascarando problemas que só apareceriam depois, em Postgres.
- Descartado por não preparar o projeto para o cenário real de mercado, onde bancos relacionais persistentes e containerizados são o padrão.

### 🟢 Postgres via Docker
- Reflete o que é usado em produção na grande maioria dos projetos reais com Spring Boot.
- Força o aprendizado de configuração de conexão, volumes Docker e persistência real de dados entre reinicializações.
- Alinhado ao padrão *database-per-service*: cada serviço com seu próprio container Postgres, reforçando o isolamento entre os bounded contexts.
- Integra naturalmente com o `docker-compose.yml` do monorepo, junto dos demais serviços.

## ⚖️ Consequências

**✅ Positivas:**
- Ambiente de desenvolvimento mais próximo da realidade de produção.
- Aprendizado prático de Docker, volumes e configuração de datasource por serviço.
- Dados persistem entre execuções, permitindo testar cenários mais realistas.

**⚠️ Negativas / trade-offs:**
- Setup inicial mais lento que H2 — é preciso ter o Docker rodando para subir qualquer serviço.
- Testes automatizados podem exigir configuração adicional (ex: Testcontainers) caso se queira evitar depender do Postgres local para rodar a suíte de testes.
